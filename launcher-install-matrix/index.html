    Launcher install matrix (internal roadmap)¶

    Scaffolding for updating and implementing the per-launcher install paths and the pack build scripts. Sources of truth, in order:

    1. Original KUMI PowerShell installer — TemporaryDetectRef/OriginalKumiScripts/KUMI.ps1 (v5.5.1). The Go install modules under internal/kumi/install/ are direct ports of its menu cases.
    2. Reference machine dumps — TemporaryDetectRef/MachineTest_01/ and TemporaryDetectRef/machine test 2/launcher-trees-2026-07-11_1415/ (produced by scripts/dump-launcher-trees.ps1, v4). Every layout claim below marked (verified) was read from those trees.
    3. Current code — detection internal/kumi/detect.go, layout planning + generation registry internal/kumi/packformat.go (launcherTargets), writers internal/kumi/gen_launchers.go, legacy modules internal/kumi/install/*.go, hosted flow internal/kumi/hostedpack.go.

    The two install paths¶

    • Legacy path (ported from KUMI.ps1): per-launcher buttons → Service.installX() (launchers.go) → install.X(...) → find root → create <root>\<subdir>\TurtelSMP5 → download a fixed ZIP. The legacy ZIPs are dead: they are Discord CDN attachment links (service.go consts) that now carry expiring signatures — the Modrinth URL's embedded ex= stamp is long past. Most launchers never had a ZIP at all and fall through to "No ZIP URL configured".
    • Modern path (hosted .polypack): download from the pack registry → extractAndVerifyPack → PlanInstallDirs → extract overrides into the game dir → GenerateLauncherFiles writers → per-file integrity verification. Launcher-agnostic and already reference-verified for the layouts below.

    Migration goal: every legacy button becomes a pack-driven install — the per-launcher module keeps only root resolution (detection candidates), and layout + config generation come from launcherTargets. The staging scaffold for this is internal/kumi/install/packflow.go (PackInstance).

    Install modes¶

    Implemented in internal/kumi/installmodes.go and applied by extractAndVerifyPack between layout planning and extraction. The UI requests a mode via payload.Extra["mode"] (both the hosted and local pack paths accept it); unknown/empty values resolve as auto, so an outdated frontend can never break installs. PackInstance carries the mode through to its stager for the migrated legacy buttons.

    Mode Existing game dir treatment User data
    auto update when the dir carries .polyforge-pack.json, else install —
    install Legacy lay-down: shipped files overwrite same-path files, everything else untouched untouched
    update Sweeps files the OLD pack shipped that the NEW pack dropped (candidates come only from the old manifest's overrides list), then extracts untouchable by construction
    reinstall Repair: same sweep + full re-extract restores missing/modified files (VerifyInstalledPack reports which) untouchable by construction
    clean Quarantines the entire game dir into .polyforge-quarantine\<timestamp>\ first — generalizes KUMI.ps1's "not-turtel" move; nothing is deleted moved to quarantine, recoverable

    Notes: update/reinstall on a dir without a record fall back to install; packs that predate per-file manifests cannot be swept (logged as such); PlanPackUpdate (same file) powers "update available" previews via ComparePackMods. Clean covers the game dir only — launcher instance metadata is regenerated by the config writers.

    Build scripts¶

    • scripts/package-modpack.ps1 builds the .polypack (manifest + launchers + overrides). It emits a launchers.json entry for every launcher above, plus a per-launcher status field (ready / verify / parked) mirroring this matrix so the installer and website can gate options without a schema change (LaunchersFile decodes entries as open maps).
    • scripts/dump-launcher-trees.ps1 (v4) is the evidence pipeline: rerun it on the reference machine after any launcher update and re-verify this matrix against the FILES\ copies before flipping a status to ✅.
    • scripts/wails-build.ps1 / docs/building.md cover the app binary itself and are unaffected by per-launcher work.
